# Dealer Kavach Admin — Mobile Usability / Friction Audit

Scope: the phone-responsive refactor of the **admin** portal (`mdg-admin/`), as used by
internal admins and super-admins on their own phones (360–430px) inside the Expo WebView
shell. This is a review of the shipped code against the mobile spec
(`admin-mobile-responsive-spec.md`) and against practical thumb-usability on a small screen.

"Friction" here = thumb-reachability, tap-target size, clarity of the primary action, hidden/
off-screen controls, information density, and any place a task becomes hard or error-prone on a
phone.

This is a findings document only — **no source was changed**. Fixes are described precisely enough
to batch with the UAT defects afterward.

**Counts:** 2 × P1 · 5 × P2 · 8 × P3

Severity key: **P1** blocks or badly hurts a mobile admin · **P2** a real friction/error trap on a
common path · **P3** polish, small tap targets, copy.

## P1 — fix first

| ID | Screen / Component | Issue | Sev | Concrete fix (file + change) |
|----|--------------------|-------|-----|------------------------------|
| F1 | **Staff & points tab** — `src/pages/dealers/DealerStaffTab.tsx` | Spec §5.2 required all five tables here to become card-stacks below `md`; **none were converted**. All are raw `<Table>` (which is `overflow-x-auto`). At 360px the Leaderboard (5 col), Roster (6 col), In-progress draft (3 col), Finalized submissions (6 col) and Award history (6 col) horizontal-scroll, and the **rightmost `Actions` column is off-screen** — so **Edit / Remove worker** (Roster) and **Undo** (Award history) can only be reached by sideways-scrolling a table that also lives inside the page's vertical scroll. This is the dealer's core points workflow (award → reconcile → undo → manage roster) and it is effectively unusable one-handed. | P1 | Import `MobileCardList` from `@/components/ui`; wrap each existing `<Table>` in `<div className="hidden md:block">` and add a parallel `<MobileCardList>` (matches the pattern already used in `DealersPage`/`AllUsersPage`). Suggested cards: **Leaderboard** primary `#{rank} {employeeName}`, `primaryRight` = points (`tabular-nums font-semibold`) `/ target`, `meta` = status chip · `{awardCount} awards`. **Roster** primary = name + designation, `primaryRight` = status chip, `meta` = `Window {pointsInWindow} · Lifetime {totalPoints}` (+ phone), `actions` = `grid grid-cols-2 gap-2` of Edit / Remove(Reactivate) (`min-h-11`). **Draft** primary = `employeeName`, `secondary` = work label, `primaryRight` = points. **Finalized** primary = `formatDate(workDate)`, `primaryRight` = points, `meta` = `{employeeCount} workers · {entryCount} entries · {awardedByName}`, hardcopy 44×44 thumbnail in `actions` (opens the existing photo `Dialog`). **Award history** primary = worker, `secondary` = work label + note, `primaryRight` = points, `meta` = `{workDate} · {awardedByName}`, `actions` = full-width Undo (`min-h-11`). |
| F2 | **Work list tab** — `src/pages/dealers/DealerWorkListTab.tsx` | Same omission: spec §5.2 required the **Default works** (4 col) and **Custom works** (6 col) tables to be card-stacks; both are still raw `<Table>`. The **Visibility toggle (Shown/Hidden)** — literally the only purpose of this tab — sits in the rightmost column and is off-screen at 360px, as do custom-work **Edit / Remove**. The admin can't tell what's shown/hidden or change it without horizontal-scrolling. | P1 | Same treatment as F1. **Default works** card: primary = `labelEn` (+ `labelHi`/`code` as secondary), `primaryRight` = points, `actions` = full-width Shown/Hidden toggle button (`min-h-11`, keep the `Eye`/`EyeOff` leftIcon). **Custom works** card: primary = `labelEn` + `labelHi`, `primaryRight` = points + status badge, `meta` = domain · distribution · pricing badge, `actions` = `grid grid-cols-2 gap-2` Edit / Remove. (Cards carrying `actions` are non-tappable per `MobileCardList` — correct here.) |

## P2 — real friction on a common path

| ID | Screen / Component | Issue | Sev | Concrete fix (file + change) |
|----|--------------------|-------|-----|------------------------------|
| F3 | **Detach service / Delete Kavach item** — `src/pages/dealers/DealerServicesTab.tsx` (`onDelete`, line 87) and `src/pages/dealers/DealerKavachTab.tsx` (`onDelete`, line 382) | Both destructive actions gate on `window.confirm(...)`. In the Expo WebView a native JS `confirm()` is a jarring system alert that breaks the app illusion, is unstyled, and — depending on how the shell wires JS dialogs — can be silently suppressed (returning `false`, so nothing happens) or shown without the expected buttons. Every other confirm in the app is an in-app sheet/dialog. | P2 | Replace each `window.confirm` with an in-app confirm using the existing responsive `Dialog` (it is already a bottom sheet on mobile) — mirror the pattern in `DealerStaffTab`'s Undo dialog: hold a `confirmTarget` state, render a `Dialog` with a danger-styled footer button. Keeps the destructive tap deliberate and on-brand. |
| F4 | **Undo award dialog** — `src/pages/dealers/DealerStaffTab.tsx` (footer, lines 715–737) | The footer can hold **three** buttons — Cancel, "Undo whole batch", "Undo this entry". `Dialog`'s footer forces `[&>*]:flex-1` on mobile (equal width) and every `Button` is `whitespace-nowrap`, so at 360px each gets ~110px and **"Undo whole batch" clips**. Worse, two destructive options sit side-by-side at thumb width — easy to hit the wrong one. | P2 | Wrap the three footer buttons in a single `<div className="grid w-full grid-cols-1 gap-2 md:flex md:justify-end md:gap-2">` so they stack full-width (and are individually large) on mobile while keeping the desktop right-aligned row. Consider ordering Cancel last (bottom) on mobile, and visually separating the two "Undo" variants. |
| F5 | **Manage user dialog (super-admin)** — `src/pages/AllUsersPage.tsx` (`ManageUserDialog`, sections at lines 517, 544, 581, 677/694) | Each section is a `flex items-center justify-between gap-3` row with a paragraph of explanatory text on the left and the action button on the right. These **don't stack on mobile**, so at 360px the descriptive copy ("Switching to Manager resets their chat threads", "Disable this login and hide them from the roster…") is squeezed into a narrow column while the button is jammed to the edge. This is the super-admin's main user-control surface. | P2 | On each of the four rows change `flex items-center justify-between gap-3` → `flex flex-col gap-2 sm:flex-row sm:items-center sm:justify-between`. The button then sits full-width under its explanation on a phone. |
| F6 | **Overview tab** — `src/pages/OverviewPage.tsx` (`RecentFailures`, lines 178–208) | Overview is one of the four fixed bottom tabs (a daily destination), but its "Recent failures" panel is a raw 4-column `<Table>` (Service, Dealer, Started, Status) that horizontal-scrolls at 360px — the only wide table left on a primary tab. ("Upcoming runs" is a `justify-between` list and mostly survives, though a long `serviceId` can crowd it.) | P2 | Card-stack `RecentFailures` like F1, or at minimum reflow to the two-line row pattern already used in `RunHistoryPage` (line 187): line 1 = StatusChip + `serviceId` (truncate); line 2 = `{startedAt}` · dealer. (Note: `OverviewPage` was outside the explicitly-listed files but is a primary tab, so it's in scope for density.) |
| F7 | **Composer** — `src/features/chat/Composer.tsx` | Two small-screen confusions on the single most-used control: (a) placeholder is `"Type a message... (Cmd/Ctrl+Enter to send)"` — the keyboard hint is meaningless on a phone (no Cmd/Ctrl; plain Enter inserts a newline), and the long string truncates in a narrow field; (b) when a conversation is `RESOLVED` the whole composer is `disabled` (greyed) with **no on-screen reason**, so it just looks broken — the fix ("Reopen") is a separate header button the admin may not connect. | P2 | (a) Drop the keyboard hint on mobile — e.g. `placeholder={isMd ? 'Type a message... (Cmd/Ctrl+Enter to send)' : 'Type a message…'}` (there's already a `useMediaQuery('(min-width: 768px)')` pattern in the codebase). (b) When `disabled` because resolved, swap the placeholder to something like "This chat is resolved — reopen to reply." so the disabled state is self-explanatory. |

## P3 — polish, tap targets, copy

| ID | Screen / Component | Issue | Sev | Concrete fix (file + change) |
|----|--------------------|-------|-----|------------------------------|
| F8 | **Sub-44px tap targets (roundup)** | Several interactive controls fall below the 44px floor the spec set: **AdminMenu avatar** (`AppShell.tsx` line 203, `px-2 py-1` around an `h-8` avatar ≈ 40px tall — and it's the *only* logout path on mobile); **Inbox filter chips** (`InboxPage.tsx` line 553, `px-3 py-1.5 text-xs` ≈ 30px tall); **Award-worker & "Include inactive" checkboxes** (`AwardPointsDialog.tsx` line 245, `DealerStaffTab.tsx` line 328 — `h-4 w-4`, 16px); **Kavach row icon-only ghost buttons** (`KavachItemRow.tsx` escalate/pause/delete ≈ 38px wide). | P3 | Give each a mobile floor: AdminMenu trigger `min-h-11 md:min-h-0`; filter chips `min-h-11 md:min-h-0` (or `py-2.5`); wrap-label checkboxes already give a bigger hit area but bump the box to `h-5 w-5` and pad the label row; Kavach icon buttons `min-w-11 md:min-w-0` (they already inherit `min-h-11`). |
| F9 | **Work list save bar** — `src/pages/dealers/DealerWorkListTab.tsx` (lines 321–361) | Save / Discard live in a card at the *top* of the tab. Spec §5.2 asked for a `sticky bottom-0` save bar on mobile: after toggling a long list of works (F2), the admin must scroll all the way back up to Save, and there's no persistent "Unsaved changes" reminder in view. | P3 | Make the summary/save `Card` `sticky bottom-0 z-10 safe-bottom md:static` (above the tab bar) so Save + the "Unsaved changes" badge stay reachable during a long hide/show session. |
| F10 | **Dealer detail tab strip** — `src/pages/DealerDetailPage.tsx` (lines 90–95) | 10 tabs in a horizontal scroller. There's a right-edge fade, but **no left-edge affordance**. For an ACTIVE dealer the default tab is `info` (2nd), which `scrollIntoView({inline:'center'})` centers — pushing `Onboarding` off the left with no hint that anything exists to the left. | P3 | Add a symmetric left fade (`before:` gradient `from-bg`, `pointer-events-none md:hidden`) shown when the strip is scrolled off `0`; or start the strip at `scrollLeft: 0` on first mount for the default tab. |
| F11 | **Bottom tab set** — `src/components/layout/navItems.ts` (`BOTTOM_TAB_ROUTES`) | Judgment call, not a defect: the four fixed tabs are Inbox / Overview / Dealers / Kavach. An admin's real daily loop is **Inbox ↔ Dealers**; "Overview" is lower-frequency monitoring, yet it holds a permanent slot while a super-admin's frequently-used **All Users** and **Activity** are two taps deep under "More". | P3 | Consider whether Overview earns a permanent slot over a higher-frequency destination (or make the 4th slot role-aware). No code-shape change needed — `BOTTOM_TAB_ROUTES` is already the single source. Leave as-is if telemetry disagrees. |
| F12 | **Kavach item row** — `src/pages/dealers/kavach/KavachItemRow.tsx` | On mobile the row reflows to a column (good), but the action cluster (`flex-wrap gap-1`) packs up to four `size="sm"` buttons, several icon-only (~38px wide), and **"Mark done on behalf of dealer"** is a single tap with no undo. In a cramped, wrapping cluster this is an easy mis-tap that silently changes the dealer's compliance score. | P3 | Widen icon-only buttons to `min-w-11 md:min-w-0`; add a little more `gap` on mobile; and consider a lightweight toast-with-undo (or a confirm sheet, per F3) for "Mark done" since it writes on the dealer's behalf. |
| F13 | **Primary create CTAs are top-anchored** | "Add dealer" (`DealersPage`), "Attach service" (`DealerServicesTab`), "Award points" (`DealerStaffTab`), "Add member" (`DealerMembersTab`) all sit at the top of the page/card — the least thumb-reachable corner on a phone. Acceptable for admins, but the highest-frequency ones ("Award points", "Attach service") force a reach to the top on every use. | P3 | No blocker. If any of these dominate usage, consider a `sticky bottom-0` action bar (above the tab bar) on that tab, matching the pattern proposed in F9 — otherwise leave. |
| F14 | **Inbox thread header density** — `src/pages/InboxPage.tsx` (mobile cluster, lines 688–745) | At 360px the header carries back (44) + title/badges + primary action (~90) + Info (44) + kebab (44). It survives via title truncation, but the status/flag badges compete with the truncating member name, so on a long "Name · Manager" + "Waiting 2h" the title can shrink to a few characters. | P3 | Minor: drop the reply-SLA `TicketFlagBadge` from the *thread* header on mobile (it's already visible in the list and the details slide-over), or move the status badge under the title (`flex-col`) so the name keeps its width. |
| F15 | **`AppShell` height — keep, don't "fix"** — `src/components/layout/AppShell.tsx` (line 110) | Note for whoever batches edits: the shell is `flex h-full` although spec §2.2 wrote `h-screen`. This deviation is **correct** — `body` owns `padding-top: env(safe-area-inset-top)`, so `h-full` (100% of `#root` = viewport minus the top inset) keeps the bottom tab bar on-screen; reverting to `h-screen` would overflow by the inset and push the tab bar below the fold on notched devices. | P3 | **Do not change to `h-screen`.** Left here only so a well-meaning cleanup doesn't reintroduce the bug. Verify on a device with a bottom safe-area inset that the bar's `safe-bottom` padding clears the home indicator. |

## What already works well (so it isn't touched)

- `Dialog` / `Drawer` / `Sheet` correctly become sticky-footer bottom sheets below `md`; the shared
  44px floors on `Button` / `Input` / `Select` / `Textarea` and the icon-button bumps in `Composer`
  are in place; the iOS focus-zoom backstop and safe-area CSS are ported.
- `DealersPage`, `AllUsersPage`, `ActivityPage`, `KavachDashboardPage` card-stacks and
  `RunHistoryPage`'s two-line rows are implemented per spec and read cleanly at 360px.
- Inbox list↔thread is URL-driven (`?c=`) so hardware-back returns to the list; the thread-actions
  kebab, long-press message menu, and reactions are bottom sheets; the details panel is a slide-over.
- `AttachServiceDialog` RJSF controls get the 44px bump and the dialog is a keyboard-safe sheet.

The two P1s are the headline gap: **`DealerStaffTab` and `DealerWorkListTab` never got the
card-stack treatment the spec called for**, leaving their action columns off-screen on a phone.
Everything else is incremental.
